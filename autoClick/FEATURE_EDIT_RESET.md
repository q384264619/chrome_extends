# 编辑任务时清除状态功能

## 🎯 功能概述

本次更新实现了编辑任务时自动清除所有执行状态的功能，确保编辑后的任务像新任务一样重新开始执行。

---

## 🐛 问题背景

**原有行为**：
- 编辑任务时，保留了原有的执行次数、最后执行时间、任务状态
- 导致编辑后的任务继续从之前的状态执行
- 用户无法"重置"任务从头开始

**示例场景**：
```
1. 创建任务A，已执行5次
2. 编辑任务A（修改选择器或时间）
3. 保存后，任务A仍然显示"已执行5次"
4. ❌ 不符合预期：编辑后应该重新开始计数
```

---

## ✅ 解决方案

### 核心逻辑

当用户编辑并保存任务时，系统会：

1. **清除执行次数** - `executionCount: 0`
2. **清除最后执行时间** - `lastExecuted: null`
3. **重置任务状态** - `status: 'pending'`
4. **确保任务启用** - `enabled: true`
5. **取消旧闹钟** - background.js自动清除所有闹钟
6. **重新调度** - 根据新配置重新创建闹钟

---

## 🔧 技术实现

### popup.js - 任务更新逻辑

```javascript
if (editingTaskId) {
    // 更新任务 - 编辑时清除所有执行状态，重新开始
    const index = tasks.findIndex(t => t.id === editingTaskId);
    if (index !== -1) {
        const existingTask = tasks[index];
        console.log(`[任务编辑] 清除任务 "${existingTask.name}" 的旧状态`);
        
        tasks[index] = {
            ...existingTask,  // 保留原有所有字段
            
            // 更新用户可编辑的字段
            name: formData.name,
            selector: formData.selector,
            timeMode: formData.timeMode,
            freqMode: formData.freqMode,
            triggerMode: formData.triggerMode,
            execTime: formData.execTime,
            intervalSeconds: formData.intervalSeconds,
            cycleType: formData.cycleType,
            skipHolidays: formData.skipHolidays,
            weekdays: formData.weekdays,
            monthlyDay: formData.monthlyDay,
            
            // ⚠️ 清除所有执行状态，重新开始
            executionCount: 0,              // 重置执行次数
            lastExecuted: null,             // 清除最后执行时间
            status: 'pending',              // 重置状态为待执行
            enabled: true                   // 确保任务启用
        };
        
        console.log(`[任务编辑] 任务 "${formData.name}" 已更新，状态已重置`);
        console.log(`[任务编辑] 执行次数: 0, 状态: pending, 最后执行时间: null`);
    }
}
```

**关键点**：
- ✅ 保留任务ID和创建时间等元数据
- ✅ 更新用户修改的配置字段
- ✅ 强制重置所有执行相关状态
- ✅ 详细的日志输出便于调试

### background.js - 闹钟管理

```javascript
async function scheduleAllTasks(tasks) {
    try {
        // ⚠️ 先清除所有旧闹钟
        await alarmsClearAll();
        console.log('[自动点击助手] 清除所有闹钟');

        // 重新调度所有启用的任务
        let scheduledCount = 0;
        for (const task of tasks) {
            if (task.enabled && task.status !== 'completed') {
                scheduleTask(task);
                scheduledCount++;
            }
        }
        
        console.log(`[自动点击助手] 已调度 ${scheduledCount} 个任务`);
    } catch (error) {
        console.error('[自动点击助手] 调度任务失败:', error);
    }
}
```

**工作流程**：
```
1. 用户点击"保存"按钮
   ↓
2. popup.js更新任务数据（清除状态）
   ↓
3. 保存到chrome.storage.sync
   ↓
4. 发送TASKS_UPDATED消息到background
   ↓
5. background调用scheduleAllTasks
   ↓
6. 清除所有旧闹钟（包括被编辑任务的闹钟）
   ↓
7. 重新调度所有启用的任务
   ↓
8. 为编辑后的任务创建新闹钟
```

## 💡 设计理由

### 为什么编辑时要清除状态？

**理由1：语义清晰**
```
编辑 = 修改配置 + 重新开始
而不是：修改配置 + 继续执行
```

**理由2：避免混淆**
```
如果不清除状态：
- 用户修改了选择器，但执行次数仍然是旧的
- 用户不知道新的选择器是否有效
- 统计数据不准确

清除状态后：
- 执行次数反映新配置的执行情况
- 统计数据准确可靠
- 用户可以清楚看到新配置的效果
```

**理由3：符合直觉**
```
类比：
- 重置游戏进度 → 从第1关重新开始
- 重置计时器 → 从0开始计时
- 编辑任务 → 从0次执行开始
```

**理由4：便于测试**
```
场景：测试不同的选择器
1. 创建任务，选择器A，执行5次
2. 编辑任务，改为选择器B
3. 如果不清除：显示"已执行5次"（实际是选择器A的执行次数）
4. 清除后：显示"已执行0次"，等待选择器B的执行
```

### 保留哪些字段？

**保留的字段**（任务元数据）：
- ✅ `id` - 任务ID（保持不变）
- ✅ `createdAt` - 创建时间（历史记录）
- ✅ 其他内部字段（如果有）

**清除的字段**（执行状态）：
- ❌ `executionCount` - 执行次数（重置为0）
- ❌ `lastExecuted` - 最后执行时间（清除）
- ❌ `status` - 任务状态（重置为pending）
- ❌ `enabled` - 强制设为true（确保启用）

**更新的字段**（用户配置）：
- ✏️ `name` - 任务名称
- ✏️ `selector` - CSS选择器
- ✏️ `timeMode` - 时间模式
- ✏️ `execTime` - 执行时间
- ✏️ `freqMode` - 频率模式
- ✏️ `intervalSeconds` - 间隔秒数
- ✏️ `triggerMode` - 触发模式
- ✏️ `cycleType` - 循环类型
- ✏️ `weekdays` - 星期选择
- ✏️ `monthlyDay` - 月度日期
- ✏️ `skipHolidays` - 跳过节假日

## 🐛 故障排查

### 问题1：编辑后执行次数未清零

**可能原因**：
- popup.js代码未正确更新
- 插件未重新加载

**解决**：
1. 检查popup.js中是否有以下代码：
   ```javascript
   executionCount: 0,
   lastExecuted: null,
   status: 'pending',
   enabled: true
   ```
2. 重新加载插件
3. 查看Console日志：
   ```javascript
   [任务编辑] 清除任务 "xxx" 的旧状态
   [任务编辑] 执行次数: 0, 状态: pending
   ```

---

### 问题2：编辑后闹钟未更新

**可能原因**：
- TASKS_UPDATED消息未发送
- background未正确处理消息

**解决**：
1. 检查Background Console日志：
   ```javascript
   [消息处理] 任务调度完成
   [自动点击助手] 清除所有闹钟
   [自动点击助手] 已调度 X 个任务
   ```
2. 确认闹钟已重新创建：
   ```javascript
   chrome.alarms.getAll(alarms => console.log(alarms));
   ```

---

### 问题3：编辑后任务仍为禁用状态

**可能原因**：
- enabled字段未被强制设为true

**解决**：
1. 检查popup.js中的更新逻辑
2. 确认包含：
   ```javascript
   enabled: true  // 确保任务启用
   ```
3. 查看UI是否显示"启用"状态
